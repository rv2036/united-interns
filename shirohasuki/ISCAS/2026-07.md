### 本月工作总结

本月主要围绕为 buddy-examples 新增离线量化框架，以及在 Nvidia GPU 通路上做量化精度损失评估展开，主要内容如下：

1. 量化框架
- 新增 `framework/quant` 离线权重量化框架，以 BWQ 包格式统一承载量化权重与 scale，并转入 rax 包的layout
- 已支持 i8 对称量化（per-tensor / per-channel）以及 OCP MXFP4 / MXFP8 块量化
- 量化损失评估分为离线的权重 NMSE 评估与在线的 Accuracy 评估
- 为 LeNet / MobileNetV3 / ResNet18 / YOLO26 接入 i8 量化脚本，为 Bert / Qwen3 接入 MXFP 量化脚本

2. 基于 Nvidia GPU 的精度损失评估
- 在 buddy-examples 中新增 nv 作为新的后端，实现 TOSA → Linalg → GPU → NVVM 的端到端编译与运行通路
- 基于量化重建权重回灌 PyTorch 模型，用 PPL / 分类 loss 等指标评估 MXFP / i8 相对全精度的精度损失

3. bug修复
- 修复 `convert-memcpy-to-gpu` 对非 identity layout 的 `memref.copy` 处理，改为先转 `linalg.generic`，并拒绝残留的 strided copy
- 统一 `testutils.h` 中非 RISC-V 架构的 cycle 读取实现


# 本月提交的PR

[[models][Quant] Add new offline weights quantisation framework](https://github.com/buddy-compiler/buddy-examples/pull/14)

该 PR 将上述离线量化能力落地到 buddy-examples：在仓库侧接入 `framework/quant` 与各模型的量化/PPL 脚本，并扩展 `archs/nv`（含 MiniMax-H3 FL2VA/Ref2VA）以便在 Nvidia GPU 上跑通量化前后对照，初步结果如下。该PR的量化策略还在优化中，准备在八月继续整理优化后合并。

| 模型 | 模式 | 权重 NMSE | 输出 |
|------|------|-----------|------|
| LeNet | i8 ch / tensor | 5.8e-5 / 1.6e-4 | top1 9900 / 9899  |
| ResNet18 | i8 ch / tensor | 1.7e-4 / 5.1e-2 | top1 9900 / 9895 |
| Bert | mxfp4 / mxfp8 | 1.3e-2 / 6.6e-4 | ppl_n5 20.2 / 23.3 |
| Qwen3-0.6B | mxfp4 / mxfp8 | 3.4e-3 / 3.1e-4 | ppl 38.2 / 30.3（bf16 基线 31.0） |

[[Conversion][GPU] Lower strided memref.copy for GPU](https://github.com/buddy-compiler/buddy-mlir/pull/869)

该 PR 针对 NVVM 无法对非 identity layout（如 RoPE half-dim subview）做 `gpu.memcpy` lowering 的问题，新增 `convert-strided-memref-copy-to-linalg` pass：将 strided `memref.copy` 转为 `linalg.generic`，再走 parallel-loops → GPU kernel；同时在 `convert-memcpy-to-gpu` 中拒绝尚未转换的 strided copy，避免静默生成错误 IR。
