### 本月工作总结

本月主要围绕 `ruyi-serving` 的模型默认 token 上限修复和 `compute_server` 模型常驻内存链路开展工作。完成了默认 `max_tokens` 封顶修复并合入 Upstream；随后实现 `server_process` 运行方式，让 `compute_server` 能启动并复用本地 buddy-server 子进程，补齐 runtime 配置校验、SSE 流式转发、真实 buddy-server E2E 验证、子进程主动回收和故障诊断增强。

### 本月提交的PR

- [RuyiAI-Stack/ruyi-serving#30: Add server_process runtime for persistent buddy-server](https://github.com/RuyiAI-Stack/ruyi-serving/pull/30) - 未合入，当前开放；在已合入 `server_process` 基础上继续增强子进程故障诊断，新增 child `stdout/stderr` ring buffer、异常时日志 tail 输出、主动 reaper 诊断，以及 `exited_before_ready`、`exit_code=N`、`signal=9`、`oom_suspected`、`startup_timeout`、`request_timeout`、`stream_idle_timeout` 等结构化分类。后续根据 review 将分类从异常展示字符串中拆出，改为内部 enum/struct 驱动，字符串只用于展示。

### 本月合并的PR

- [RuyiAI-Stack/ruyi-serving#25: Fix default max tokens cap](https://github.com/RuyiAI-Stack/ruyi-serving/pull/25) - 6 月 3 日合入；修复调用方未显式传入 `max_tokens` 时，`default_max_tokens` 大于 `max_max_tokens` 会导致 API Server 返回 400 的问题。实现上将自动使用的默认 token 数封顶到模型上限，同时保留显式超限请求返回 400 的行为，并补充非流式和流式回归测试。
- [RuyiAI-Stack/ruyi-serving#28: Add HTTP child process compute runtime](https://github.com/RuyiAI-Stack/ruyi-serving/pull/28) - 6 月 28 日合入；为 `compute_server` 新增可选 `server_process` runtime，默认仍保持 `oneshot_cli`。该 runtime 由 `compute_server` 启动本地 buddy-server 子进程，分配 `127.0.0.1` 端口，等待 `/health` ready 后通过 `/completion` 转发非流式与 SSE 流式请求；模型配置不变时复用子进程，配置变化或 reload 时清理旧 runtime。
