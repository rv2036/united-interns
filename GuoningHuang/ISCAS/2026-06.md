### 本月工作总结

本月主要围绕 buddy-mlir 项目中的模型运行时扩展与多模态模型接入展开工作。在现有 `buddy-cli` / `.rax` 运行时和 `tools/buddy-codegen/build_model.py` 构建入口基础上，新增了两个非传统 LLM 推理模型的端到端接入路径：一是将 `openai/whisper-base` 作为 encoder-decoder ASR 模型接入 buddy-runtime，支持音频输入、单 forward 图编译、WhisperRunner 插件加载、音频预处理与贪心解码；二是将 Qwen3-VL-2B-Instruct 以 OCR 场景为目标接入 `buddy-cli`，实现图像输入、视觉编码器与文本解码器分离编译、C ABI shim、模型专用 codegen pipeline 和运行时插件。

同时，对通用模型构建逻辑进行了扩展，使 `buddy_add_model` 不再只服务于 DeepSeek-R1 这类 LLM prefill/decode 模型，而是开始支持 `single_forward`、多模态定制 pipeline、模型专用 importer、manifest generator、额外运行时依赖和资源文件打包等能力，为后续更多非 LLM 或多模态模型纳入 `.rax` 运行体系提供了基础。

### 本月提交的PR

- https://github.com/buddy-compiler/buddy-mlir/pull/818 新增 Whisper ASR 模型接入（`[models] Add Whisper (encoder-decoder ASR) as a buddy-cli/.rax model`），在 `models/whisper` 下添加 spec、import/manifest codegen、`WhisperRunner` 与 runner plugin，并为 `buddy-cli` 增加 `--audio` 输入参数。该 PR 将 Whisper 的单 forward encoder-decoder 推理路径打包为 `whisper.rax`，支持通过 `tools/buddy-codegen/build_model.py` 构建，并已由评审反馈确认可正常编译运行、完成语音识别。

- https://github.com/buddy-compiler/buddy-mlir/pull/819 新增 Qwen3-VL OCR 模型接入（`[models] Add Qwen3-VL OCR model for buddy-cli`），在 `models/qwen3_vl` 下添加模型专用 codegen、vision/decoder C ABI shim、runner plugin、variant spec 和 README，并为 `buddy-cli` 增加 `--image` 输入参数。该 PR 支持固定图像网格 `[1,14,28]` 下的 `--image + --prompt` OCR 流程，视觉编码器和文本解码器分别编译为 buddy kernel，再由运行时完成 embedding splice 与 greedy decode；当前评审指出 `.rax` 文件格式还需补齐所有运行时所需内容，后续需要按 DeepSeek-R1 的 `.rax` 打包格式继续修正。
