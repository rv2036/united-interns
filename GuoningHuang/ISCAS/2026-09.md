### 本月工作总结

本月主要围绕 buddy-mlir 的 DeepSeek-R1 packed decode 运行时修复与 SG2044 平台验证展开工作。调整生成的 `ModelSession`，使 decode 直接复用会话状态，移除逐 token 的 KV cache 和 logits 回拷贝及临时结果重置；同时将 `buddy-cli` 默认改为仅加载模型插件，解决主程序静态链接的旧 `ModelSession` 抢占插件符号、导致 packed decode 错读普通权重的问题。通过在 prefill/decode 阶段边界切换普通权重和打包权重，避免两份约 6.7 GB 的 FP32 权重同时驻留，SG2044 上测得峰值 RSS 为 7,236,680 KB，低于此前约 14.5 GB 的占用。

此外，修复生成步数预算错误，使 `--max-tokens` 按新增 token 数量计数，解决长 prompt 配合较小生成上限时跳过 decode 的问题；为 packed decode 向量化 pass 新增 `panels-per-iteration` 参数，使一次 A 标量加载可供多个相邻权重 panel 使用，并接入 codegen 配置。SG2044 上完成 CLI 生成、长 prompt 生成及服务端连续请求验证，确认权重路由和会话复用流程正常。

本月还完成 FP32/FP16 packed decode 与分层 KV cache 的组合支持，扩展共享 buddy-codegen pipeline，实现各档 decode 图的权重打包、prefill/decode 权重路由，以及 FP16 KV cache 升档拷贝和 logits 转换。新增 64、128、256、512、1024 五档 cache 配置，并完成完整模型的分层边界、缓存溢出和会话重置验证。在 Intel Xeon Platinum 8488C 上，FP32/FP16 decode 吞吐分别达到 34.0972 和 61.2375 tokens/s。

同时，上月提交的 RISC-V Zfh/Zvfh 可选构建支持于 9 月 15 日合入主线，将 SG2044 上 DeepSeek-R1 FP16 推理使用硬件半精度标量和向量指令的能力接入示例及 buddy-codegen 构建路径。

### 本月提交的PR

- https://github.com/buddy-compiler/buddy-mlir/pull/931 修复 DeepSeek-R1 decode 会话状态复用（`Fix DeepSeek R1 decode session state reuse`），在非分层生成路径中直接复用 decode 状态，移除多余的缓存回拷贝；新增默认关闭的 `BUDDY_CLI_LINK_BUILTIN_MODELS` 开关，避免静态模型与动态插件之间的 ELF 符号抢占；实现普通/打包权重分阶段加载，并修复 `runGeneration` 的新增 token 预算计算。同步新增 packed decode 的多 panel 迭代参数、FP32/FP16 模型配置和 RISC-V 插件交叉编译辅助脚本。在 SG2044、8 线程环境下，`hello` 的生成输出恢复为 `Alright,`，46-token prompt 配合 `--max-tokens 8` 可执行 7 次 decode，服务端连续两次 `/completion` 请求均返回预期结果。

- https://github.com/buddy-compiler/buddy-mlir/pull/968 支持 FP32/FP16 packed decode 与分层 KV cache 组合使用（`[tools] Support FP32/FP16 packed decode with tiered KV cache`）。扩展共享 buddy-codegen pipeline，对每个 cache tier 的 decode 图进行权重打包并导出独立参数文件，保持 prefill 使用普通权重、decode 使用打包权重；新增 64、128、256、512、1024 五档 cache 配置，各档 prefill 均使用融合 FlashAttention，并按配置的数据类型完成 KV cache 升档拷贝和 FP16 logits 转换。
