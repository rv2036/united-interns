### 本月工作总结

本月主要围绕 buddy-mlir 的模型生态扩展与 DeepSeek-R1 CPU decode 性能优化展开工作。在模型接入方面，新增 BGE-M3 稠密向量模型和 ProteinGLM 蛋白质序列模型的 `buddy-cli` / `.rax` 端到端推理路径，并将通用模型构建框架扩展至 encoder 类 `single_forward` 模型，支持模型专用 importer、manifest generator、资源打包和运行时依赖配置；同时完成上月提交的 Whisper 语音识别与 Qwen3-VL OCR 模型接入并合入主线。

在推理优化方面，重写 DeepSeek-R1 decode 阶段的 GQA attention kernel，通过寄存器累加、分块向量化 softmax、head 并行和 Flash-Decoding 将单层算子延迟从 0.690 ms 降至 0.093 ms，获得 7.4 倍加速；针对 decode GEMV 的跨页访存问题，引入权重 panel packing 和配套向量化 pass，使 decode 吞吐约提升 2 倍，其中 lm head 延迟由 6.03 ms 降至约 1.5 ms。两项优化均保持生成 token 与优化前完全一致。

### 本月提交的PR

- https://github.com/buddy-compiler/buddy-mlir/pull/839 为 decode 阶段的 matmul 权重实现 panel packing（`[frontend][midend] Panel-pack decode matmul weights (DeepSeek-R1 decode ~2x)`），在导入时将静态权重重排为连续访存布局，并新增 packed decode 向量化 pass、独立参数文件、构建配置、正确性测试及文档。DeepSeek-R1-Distill-Qwen-1.5B 的 decode 吞吐约提升 2 倍，lm head 延迟由 6.03 ms 降至约 1.5 ms，生成结果与未打包版本逐 token 一致。

- https://github.com/buddy-compiler/buddy-mlir/pull/837 重写 decode GQA attention kernel（`[frontend] Speed up decode GQA attention by 7.4x`），通过将累加器保留在寄存器中、分块并向量化 softmax、并行处理 attention heads，以及按 KV 序列切分的 Flash-Decoding，提高核心利用率并缩短在线 softmax 依赖链。单层算子延迟由 0.690 ms 降至 0.093 ms，获得 7.4 倍加速，生成 token 保持完全一致。

- https://github.com/buddy-compiler/buddy-mlir/pull/828 新增 ProteinGLM 模型接入（`[model] Add ProteinGLM buddy-cli integration`），在 `models/proteinglm` 下实现模型专用 importer、RHAL manifest generator、`InferenceRunner`、runner plugin、模型配置和使用文档，并扩展 `buddy_add_model` 对 `single_forward` 模型、自定义构建脚本、资源打包、动态库命名及运行时链接选项的支持，实现蛋白质序列模型通过统一 `.rax` 流程构建和运行。

- https://github.com/buddy-compiler/buddy-mlir/pull/827 新增 BGE-M3 稠密向量模型接入（`[models] add bge-m3 model example`），在 `models/bge_m3` 下添加 importer、manifest generator、tokenizer、`InferenceRunner`、runner plugin、模型配置和文档，并将通用构建 pipeline 扩展至 encoder 类 `single_forward` 模型，使 BGE-M3 可通过 `buddy-cli` / `.rax` 完成端到端文本 embedding 推理。
